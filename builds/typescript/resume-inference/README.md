# Resume Builder brokered inference

This directory is the accepted Spec 03 broker plus the Spec 06 implementation and a review-only Spec 07 Milestones 3–5 implementation candidate for twelve Resume Builder inference purposes. `resume_strategy`, score-free `tailoring_plan`, independent `resume_craft_evaluate`, and bounded `resume_craft_repair` are operational. Spec 05 M5 exposes the broker through the thin [protected app capability adapter](../app-inference/README.md). Both remain deliberately separate from `engine/loop.ts`: requests cannot discover or call tools, cannot enter the chat retry loop, and cannot select a provider, model, credential, or capability.

`ImmutableInferenceSnapshotBuilder` resolves only exact, scoped revision IDs and admits only confirmed factual evidence. Historical schema-2 job-evidence dispositions other than `answered` remain readable but are filtered out of the fact snapshot and its revision manifest. Strategy receives confirmed facts, exact coverage heads, deterministic evidence annotations, presentation preferences, and accepted `resume-quality.md` revision-3 identity. General generation receives those exact facts and coverage heads plus one persisted strategy and the same quality identity. Craft evaluation receives one current proposal, strategy, optional target analysis, host-derived truth/structure/mechanical gate evidence, and the provisional RB7-OQ-1 policy identity. Repair additionally receives one failing report and one exact statement/correction-class scope. The app cannot supply or override deterministic gate blocks. Interview assistance uses `resume.interview-assist.v2`: the host supplies the exact ranked opportunity, and prompt policy 7 permits the model to phrase it only. `ResumeInferenceBroker` validates the request and every data-block digest before resolving the owner's live provider, then uses `completeStructuredNoTools` with `tools: []`, fixed prompt policy 7, strict purpose schemas, bounded token/time/attempt limits, and the caller's abort signal.

The broker never exceeds the accepted two-provider-call ceiling. Empty or schema-invalid output can use the second call for structural repair. A schema-valid result that fails deterministic validation can instead use that call for an evidence-validation repair containing only the prior structured result and safe validator findings; the model must preserve every unflagged statement exactly. If structural repair consumed the second call, a resume draft gets one local deterministic fallback that rewrites only rejected or structurally missing lines from their cited confirmed facts. The fallback makes no provider call, preserves valid statements, and must pass the same deterministic gate before completion. Auth, quota, rate-limit, policy, cancellation, network, and visible/ambiguous failures still do not fall back or retry.

Raw failed provider output is not retained or audited. Standard audit callbacks receive only opaque operation/request IDs, purpose/schema/policy IDs, model class, attempt, bounded usage availability, status, timing class, typed error code, safe validator findings on terminal rejection, and the content-free repair classification on success.

Cancellation is checked before and after provider resolution, before each bounded attempt, immediately after every provider response, and before validation/commit. A provider response that arrives after abort is projected as cancelled and cannot become a completed result. Broker idempotency hashes the immutable semantic request rather than host-generated request/timestamp fields, so a reconnect rebuild reuses the same completed operation while any snapshot, policy, schema, identity, or budget change conflicts.

The deterministic gate resolves every cited fact identity to the immutable confirmed snapshot, requires exact job source spans, validates targeted lineage, and conservatively rejects lexical/protected numeric, date, title, and URL drift. The independent craft extractor adjudicates C1–C7 and T1–T3 without a score and rejects model disagreement on mandatory findings. Evidence-limited passage is explicitly provisional pending RB7-OQ-1: C1–C3 and every must-use item still pass, optional gaps remain visible, and neither padding nor bypass is allowed. Repair preserves title, section order, statement set/order/shape, support IDs, and every unnamed statement exactly; a source proposal has at most one attempt. Any original or repaired result with an error or blocking finding blocks approval.

Target-fit analysis requires exactly one approved general resume, its persisted strategy, one immutable job snapshot, and one evidence matrix. The host adds the fixed `resume.target-fit-policy.v1` block and independently recomputes the provider plan. The current policy identity is `braindrive.resume-builder.target-fit.provisional-rb7-oq3` version 1: it is the draft plan's suggested default, not an accepted answer to open question RB7-OQ-3. It permits a child only for at least one supported core requirement, or at least two supported transferable requirements, plus a supported selection/order/emphasis change. Ambiguous evidence fails closed; shortening or wording-only changes cannot satisfy the material-change gate. Targeted drafting then receives the persisted passing analysis and may change only its named parent statements. Unsupported and partial rows never become claims, and target text cannot become a resume title or unplanned keyword change.

Guidance receives exactly one immutable resume definition and one deterministic quality-finding block. Results are bounded to strengths, gaps, ATS/structure observations, interview preparation, and at most three optional follow-up questions. Every item carries one of the supplied evidence labels; score, ranking, prediction, guarantee, and unsupported competence language are rejected. Malformed or unavailable provider output uses a deterministic local projection from the same finding block. It never becomes resume content and never changes approval state.

Resume-generation policy asks compatible models to follow the exact strategy's history shape, evidence priorities, role-density classes, section order, contextual skill placement, and optional summary decision. Density classes guide evidence selection and are not bullet quotas. Every must-use identity must appear with claim lineage or one visible bounded omission reason. Structured interview values keep a job and its accomplishments associated by an immutable fact revision, but their JSON markers and internal identities are forbidden from visible resume text. Coaching preferences can guide the draft but cannot be copied into experience. A summary is omitted when the snapshot cannot support distinct positioning.

## Compatibility gate

`ModelCompatibilityRegistry` accepts only version-1 conformance records that passed 100% schema success and the zero-unsupported-claim gate. Prompt policy version 7 and interview-assist v2 invalidate prior policy/output pairings. `model-compatibility.json` is intentionally empty and every live purpose fails closed until an owner-authorized credentialed conformance run produces current per-purpose evidence. BrainDrive Models evidence would not authorize OpenRouter or Ollama identities.

`npm run resume:quality` is the credential-free Milestone 7 quality harness. It runs the fixed F1–F12 synthetic fixture suite, an independent clean-text extractor, twelve mutation cases, two clean false-blocker checks, seven persona dimensions, the F9 successor no-regression check, and an anti-overfit scan. The separate strict M7 corpus adds nine generative fixture identities, two disjoint holdouts, must-use evidence relations, eight coverage/yield journeys, seven target classes, generic/duty-only/mutation/clean craft cases, safe/unsafe repair relations, both successor paths, four artifact-parity mutations, and two normalized owner journeys. It checks sparse/substantive role density, confirmed support, contextual skills, summary support, chronology, padding, metric refusal, clean-text recovery, revision continuity, relation integrity, and semantic confirmation-friction limits.

The durable M7 report binds the full Git revision, prompt-policy digest, quality-standard digest, fixture-corpus digest, and report-schema digest. Its strict schema permits only categories, counts, statuses, and SHA-256 digests. `assertSanitizedDurableEvidence` rejects content-bearing fields and private paths. Deterministic success is scoped to credential-free checks: multi-run generation, provider conformance, human calibration, the numeric friction threshold, and retention/deletion remain independent mandatory gates. `release_ready` can become true only when every gate passes; an aggregate or holistic read cannot override any per-operation truth, structure, C1–C3, must-use, target, repair, successor, or parity failure.

`quality-evaluation.ts` defines controlled-ingestion contracts without executing controlled work. `FreshGenerationOperationSchema` requires exactly three unique operation and freshness identities for every generative fixture and authorized provider/model class. `ProviderPurposeEvidenceSchema` treats timeout, response loss, refusal, malformed output, and incompatibility as non-conformance. Human review requires one accepted calibration policy, attributable reviewer-identity digests for the independent resume-quality and non-technical owner roles, transcript/expectation/prior-score blindness, required samples, and fail-closed shared-judgment disagreement. The current repository has no accepted Spec 07 reviewer/provider/calibration/friction/retention authority, so ordinary runs correctly report these gates as blocked.

Raw synthetic review deletion is available only through `deleteRawSyntheticReviewArtifacts` with an accepted strict retention contract, a task-selected child directory below a bounded parent, and an exact sentinel binding that directory to the contract digest. Symlinks, broad targets, missing/mismatched sentinels, and unsupported filesystem objects are rejected before deletion. The returned attestation contains only policy/content digests, counts, byte totals, completion time, and deletion status—never a path or review content. When no authorized raw workspace was created, no deletion is performed and no deletion attestation is fabricated.

The live runner is deliberately opt-in and emits only registry fields. From `builds/typescript`, an operator with an already configured owner profile can run `BRAINDRIVE_RESUME_CONFORMANCE=1 npm run resume:conformance`; `BRAINDRIVE_RESUME_CONFORMANCE_PURPOSES=general_resume_draft` narrows a rerun. `BRAINDRIVE_RESUME_CONFORMANCE_DIAGNOSTICS=1` adds only validator codes and safe messages for the synthetic corpus. The runner resolves credentials through the normal vault boundary and never prints them, prompts, provider bodies, or raw model output.

The sandbox receives provider-profile and model IDs only as opaque completed-result lineage so it can persist the exact strategy/draft binding; it cannot choose or configure them. Credentials, headers, raw permissions, URLs, and paths remain excluded. The package-side MCP operations delegate to this host capability and never call a provider directly.

The isolated M6 browser journey may set `BRAINDRIVE_E2E_RESUME_INFERENCE_FIXTURE=1` through `client_web/scripts/run-isolated-e2e.mjs`. That resolver is deterministic, accepts only the structured no-tools Resume Builder call shape, and throws if asked to enter the general agent loop. The flag is absent from normal runtime and Docker configuration and never adds a production compatibility entry.
