# Credential-isolated installed-app inference capability

The current installed-app contract version 2 is app-owned. An active signed app process prepares the prompt and JSON Schema and adjudicates the returned candidate through private model-visible MCP tools. BrainDrive validates only the generic program envelope, namespaced content-free issue IDs, strict response shapes, and app/install/package authority. It resolves the owner's active provider without revealing credentials, permits at most two sequential structured no-tools calls, binds cancellation and idempotency, and returns a generic terminal result. No app-specific prompt, semantic validator, issue catalog, retry instruction, or deterministic fallback belongs in this host executor.

Resume Builder's twelve programs are shipped by the Resume Builder package at `builds/resume_builder/resources/inference-program.js`. The General output schema structurally groups each experience role and limits it to six bullets; every program's exact semantic issue IDs are fed into its one bounded retry, and eligible deterministic fallback also runs in the installed app process. If that app is absent, inactive, mismatched, or does not expose the requested program, provider resolution does not occur.

Contract version 1 is rejected. Every Resume purpose consumes a one-use `app_inference` token against the exact current owner/app/publisher/package/install/connection/view/operation/idempotency/grant/revocation/scope binding, then calls only private tools on that same verified app connection. Those tools are never exposed to the sandbox iframe.

Bridge, app-server, and authenticated owner paths share the generic installed-program executor. Canonical duplicate work coalesces in memory, and the lifecycle store atomically persists the safe terminal projection for reconnect/process replay. A reconnect may change host request IDs and timestamps without a second provider call; changing program input or identity conflicts. Cancellation aborts both the coordinator and provider call, and responses received after abort are discarded.

The generic terminal result contains only the contract and operation identity, app program identity, status, attempt count, completion mode, opaque active provider/model identities, namespaced issue IDs, structured app result, and app-supplied content digests/policy identity when persistence needs them. Those opaque identifiers do not grant provider selection or provider access. No app receives a credential, secret reference, authorization header, endpoint, raw provider body, filesystem authority, or general tool authority.

The app adjudicator returns content-free issue IDs for testing and the one bounded correction call. Resume Builder uses those IDs to identify malformed fields without retaining raw failed output in host audit data. Its General fallback remains an unapproved app result subject to every normal host-side data, evidence, review, and approval gate.

The active owner profile and model are resolved only by BrainDrive. Ollama remains keyless, BYOK OpenRouter resolves only its owner credential, and BrainDrive Models resolves only its configured credential/entitlement; none silently switches to or funds another profile. Missing or incompatible structured completion support fails closed. Resume Builder contains no provider selector.

See [SPEC-05-M5-VERIFICATION.md](SPEC-05-M5-VERIFICATION.md) for the evidence matrix and reproducible checks.

Brief Builder contributes the distinct `brief.generate@1` purpose in `brief-inference/`: fixed prompt/policy identity, owner-active compatible structured no-tools execution, two attempts, a 30-second ceiling, cancellation, and deterministic quote/owner-context grounding. Its production capability handler resolves the exact app/purpose/version through this registry and repeats current grant plus verified-manifest-purpose checks before provider execution or Brief persistence. Its synthetic corpus proves workflow and contract behavior only, not live prose quality.
